# Pressroom 需求文档 v1

> 状态：v1（2026-10-03），按 Phase 0 技术验证结论修订；v0 原稿见同目录 `requirements_v0.md`，验证结论见 `.dev/docs/others/phase0-findings.md`。
> 定位：介于功能繁杂的 Enveloppe 与收费的 Obsidian Publish 之间——**多站点、逐篇、零 frontmatter、带管理面板**的免费 Obsidian 发布插件。计划开源。
> 背景：作者现有多个 Quartz 站点用 Enveloppe 发布；Pressroom 计划替换 Enveloppe。

---

## 1. 目标与原则

- 在 Obsidian 内右键即可把**单篇笔记**发布到一个或多个站点、撤稿、取链接，体验接近 Obsidian Publish。
- **不在笔记 frontmatter 写任何字段**；发布状态与站内位置由插件自己记录。
- **站内组织与 vault 组织可以不同**：每篇笔记在站上的目录和名称可单独指定，也可跟随 vault。
- **站点之间可隔离**：同一 vault 发往多个站时，不得在站点之间产生可追溯的关联。
- 简单优先：只做发布所需的功能，不做 Enveloppe 式的大量转换选项。

## 2. 范围

**v1 支持**
- 静态站生成器：**Quartz 5**（网址规则、链接改写封装为独立模块，便于以后接入 Hugo 等）。
- 存储后端：**GitHub 仓库**（经 GitHub API 直接提交到指定分支，不走「分支 → PR → 合并」）。
- 托管平台无关：Cloudflare Pages / Netlify / GitHub Pages 等从仓库构建的方案均可。
- 仅桌面端；界面中英双语。

**v1 不做**
- 自动按规则批量发布、定时发布。
- 除 Quartz 外的生成器、除 GitHub 外的 Git 托管。
- 修改笔记内容或 frontmatter。

## 3. 站点配置（设置页）

每个站点一项，可增删：

| 字段 | 说明 |
|------|------|
| 名称 | 显示在菜单、选项卡中，如「站点 A」「站点 B」 |
| 仓库 | `owner/repo` |
| 分支 | 如 `main` |
| 内容目录 | 如 `content` |
| 站点网址 | 如 `https://example.pages.dev`，用于生成链接、打开网页 |
| 目录模式 | 手动 / 跟随 vault（见 §5） |
| 隔离 | 开启后，指向其他站点的链接一律输出为纯文本（见 §8） |

- **v1 补充（2026-10-04 用户决定）**：每个站点的「仓库 + 分支」必须唯一。manifest 位于分支根目录，同一分支的两个站点会共用发布记录、互相误判；同一仓库的不同分支允许。设置页字段校验时提示，发布等操作跳过冲突的站点。

全局设置：
- GitHub token（存 Obsidian secretStorage，不写入插件 data.json；所需权限仅 Contents 读写）。
- 排除文件夹：其中的笔记永远不能发布、也不会被双链连带（如 `Private`）。
- 双链处理默认值（见 §7）。
- 属性白名单（默认 `title`、`tags`、`date`、`description`，见 §7）。
- 界面语言跟随 Obsidian 语言（中文 / 英文）。

  ├ Pressroom：撤稿…      → 弹出站点列表（未发布的站点灰显）

- 站点列表中每项旁显示该站状态（✓ 已同步 / ● 有修改 / ↪ 已移动）。
- 只配置了一个站点时，跳过站点列表直接执行。
- 支持在文件列表中多选后批量发布/撤稿。
- 命令面板提供同样的命令，便于绑定快捷键。

## 5. 站内位置

### 5.1 站点的两种目录模式（整站政策，设置页按站点选择）

| 模式 | 含义 | 发布/移动弹窗中「按 Vault 目录」 | 「已移动」 |
|------|------|-------------------------------|-----------|
| **手动**（默认） | 站内位置完全由用户决定，与 vault 组织无关 | 一键填入当前 vault 路径与文件名的**快捷方式**，填完仍可微调；不留任何记录 | 不存在 |
| **跟随 vault** | 站内目录与名称始终 = vault 中的目录与文件名 | 强制勾选，目录与名称灰显不可改 | vault 中移动/改名后出现，同步/重排时随之挪动 |

- 没有逐篇的跟随/固定标签：笔记的位置行为完全由所在站点的模式决定。同一篇笔记发到不同站点，各按各站的模式。
- 手动站点的管理面板**不提示**「站内位置与 vault 不一致」——手动即不管 vault。
- 设计记录：曾考虑「半自动」（逐篇跟随/固定标签）模式，因概念与切换规则复杂、实际收益小而放弃；其用途由「手动 + 移动弹窗中的『按 Vault 目录』快捷方式」替代。

### 5.2 切换模式

**底线：切换模式本身绝不挪动站上任何东西**；实际挪动只发生在用户点「同步/重排」时（且会列出清单）。

| 切换 | 结果 |
|------|------|
| 跟随 vault → 手动 | 直接切换；所有笔记原地不动，「已移动」消失 |
| 手动 → 跟随 vault | 位置与 vault 不同的笔记将标记为「已移动」；需确认弹窗（N = 0 时不弹窗） |

手动 → 跟随 vault 的确认弹窗（仅统计站内路径 ≠ vault 路径的笔记）：

> **将「站点 B」设为跟随 vault？**
> 设置后，本站所有笔记的位置与名称将始终跟随 Obsidian vault。
> 你手动发布的笔记中有 **N 篇**当前发布位置与 vault 不同（▸ 展开清单）。确定后它们将标记为「已移动」；在你点击「同步」或「重排」之前，网页不会有任何变化。挪动后这些页面的网址会改变，已分享的旧链接可能失效。
> 〔取消〕〔确定〕

### 5.3 位置弹窗（首次发布 / 管理面板中移动 共用）

```
┌ 发布到「站点 B」──────────────────────────────┐
│ ☑ 按 Vault 内目录发布                          │
│ 站内目录：[ 笔记/数学/示例笔记 ▾ ]             │  勾选时自动填 vault 路径；不勾时从站上已有目录选或新建
│ 站内名称：[ 示例标题 Example Title       ]     │  预填 vault 文件名，可改
│ 网址预览：/笔记/数学/示例笔记/示例标题-…       │
│ ⚠ 与「xxx」网址冲突，请改名                     │  实时检测，冲突时不可发布
│ 双链处理：○ 纯文本  ○ 带一层  ○ 带到底         │
│                          [取消]  [发布]        │
└────────────────────────────────────────────────┘
```

- 「按 Vault 目录」：手动站点默认不勾，勾选即填入 vault 路径与文件名，之后仍可改；跟随 vault 站点强制勾选，目录与名称灰显。
- 管理面板中「站内改名/移动」打开同一个弹窗（不含双链处理一栏），预填当前站内位置；「按 Vault 目录」作为快捷方式一键填入 vault 位置，确认前可看到网址预览与冲突检查。跟随 vault 站点不提供移动（位置由 vault 决定）。
- 已发布过的笔记再次「发布」= 更新，不再弹位置设置（位置在管理面板中改）。
  - **v1 补充（2026-10-04 用户决定）**：跟随 vault 站点上「已移动」的笔记，右键发布 = **同步**：挪到新位置并更新内容，旧路径写入 aliases 让旧网址重定向；新位置冲突时拒绝并提示。
- 「发布 → 全部站点」且对其中部分站点是首次发布时：弹窗按站点分块，每块按各自站点的模式填写；已发布过的站点直接更新，不出现在弹窗里。
- **同名冲突按网址判断**：用与 Quartz 相同的 slug 规则（空格→`-`、小写、去除 `?#<>:"|*` 等）算出网址，~~与 manifest 中已有网址比较~~ **v1：与站点内容目录中的全部文件（含非 Pressroom 管理的文件）以及插件已写入的 aliases 比较**（Quartz 遇冲突只警告、后者覆盖前者，故必须由插件拦截）。`A B.md` 与 `a-b.md` 视为冲突；与所在文件夹同名的笔记（`笔记/笔记.md`）网址折叠为 `笔记/`，与 `笔记/index.md` 视为冲突。

## 6. 管理面板

- 入口：左侧 ribbon 图标点击呼出（弹窗，与 Obsidian Publish 一致），非常驻侧栏。
- 顶部：**每个站点一个选项卡**。
- 主体：该站点的**站内目录树**（看到的是网站结构），每项显示：站内名称、对应的 vault 笔记路径、状态标签。
- 单项操作：更新、站内改名/移动（仅手动站点，弹窗见 §5.3）、撤稿、复制链接、打开网页、在 vault 中打开。

### 6.1 状态模型

```
源笔记已删除 ──────────────────── 独立、互斥
源笔记存在 ─┬─ 无任何差异 ──────── 已同步
            └─ 有差异（可叠加）
                 ├ 有修改：站上内容比 vault 旧
                 └ 已移动：仅「跟随 vault」站点，vault 中位置或文件名变了
```

- 「有修改」判定：把笔记按发布规则转换后计算 git blob SHA，与仓库中对应文件的 blob SHA 比较（不依赖本地时间戳，换设备也准确）。

### 6.2 批量按钮（面板顶部，作用于当前站点）

| 按钮 | 作用对象 | 行为 |
|------|---------|------|
| 一键同步 | 有修改 或 已移动 | 推送新内容并挪到新位置 |
| 一键更新 | 有修改 | 只推内容；已移动的在**原位置**更新，「已移动」保留 |
| 一键重排 | 已移动 | 只挪位置（复用原 blob），「有修改」保留 |
| 清理已删除 (n) | 源已删除 | **先列清单确认**再撤稿；不并入上面三个按钮 |

- 手动站点没有「已移动」，因此只显示「一键更新」与「清理已删除」；「一键同步」「一键重排」仅出现在跟随 vault 站点。
- 每个批量操作合并为**一次提交**，只触发一次站点构建。

## 7. 内容转换

- **双链**：插件把 `[[笔记]]` 改写为目标笔记在**本站**的实际站内路径（因为站内名可能与 vault 名不同，不能依赖 Quartz 按文件名解析）。
  - **v1 补充**：始终输出从内容目录根算起的完整站内路径（只写文件名遇同名文件会成死链）；输出格式按站点 `quartz.config.yaml` 中 CrawlLinks 的 `markdownLinkResolution` 自动适配——shortest / absolute 输出完整路径，relative 输出相对路径；锚点保留原标题文字，由 Quartz 自行转换。
- **指向未发布笔记的链接**：发布时弹窗三选一（设置中有默认值）：
  1. 变为纯文本；
  2. 自动连带一层（直接链接的笔记一起发布，用其默认位置）；
  3. 自动连带到底（递归）。
  连带发布同样受排除文件夹约束；连带的笔记在弹窗中列出供确认。
  - **v1 修订（2026-10-04 用户决定）**：~~所有站点都提供三选一~~ → **三选一只在「跟随 vault」站点提供**，连带笔记的站内位置即其 vault 位置（无需另定默认位置）；设置中的默认值也只对跟随 vault 站点生效。**手动站点**：指向未在本站发布的笔记的链接一律为纯文本，发布弹窗列出这些笔记并说明「你可以先发布这一篇。等它们发布后，Pressroom 会提醒你更新这一篇，链接就会生效」——手动模式下每篇的位置都由用户决定，插件不替用户自动放置笔记。
  - **更新时**（跟随 vault 站点）：出现新的未发布链接时按设置默认值处理；默认值为连带时弹出连带清单确认，绝不静默多发笔记。
- **反向链接提醒（v1 新增，2026-10-04 用户决定）**：发布一篇笔记后，若本站已有其他已发布笔记链接到它（之前显示为纯文本），成功提示列出这些笔记并提供「一并更新」（一次提交）；撤稿确认框同样列出链接到它的已发布笔记，提供「一并更新，链接改为纯文本」（默认勾选），避免留下指向已删页面的链接。不自动更新：重新发布会带上这些笔记在 vault 中尚未发布的其他改动，须经用户同意。只影响一层，不会循环（重新发布已在站上的笔记不改变站上有哪些笔记、在什么位置）。
- **嵌入笔记** `![[笔记]]`（含 `![[笔记#标题]]`、`![[笔记#^块]]`）：**把被嵌入内容直接展开写入当前文章**；被嵌入的笔记不会因此单独成页、也不会被带出。展开内容同样经过本节的转换（其中的双链、图片照常处理），嵌套嵌入递归展开并防循环。
  - **v1 补充（2026-10-04 用户决定）**：展开内容包在 callout 中并显示被嵌入笔记的标题（类似 Obsidian 的嵌入样式）；被嵌入笔记在排除文件夹中时不展开，显示为纯文本名称。
- **附件/图片**：~~嵌入的附件随笔记上传~~ **嵌入的附件与普通链接指向的附件（如 `[[资料.pdf]]`）都随笔记上传**（2026-10-03 用户决定），统一存放在站点的 `assets/` 下，保留原文件名；按内容哈希判断是否同一文件——同一文件被多篇引用只存一份，同名但内容不同则自动加后缀区分。**v1：「同名」按 slug 后的网址判断**（Quartz 对附件路径同样转小写、空格转 `-`，`My Image.png` 与 `my image.png` 在站上是同一网址）。manifest 记录附件与文章的引用关系。
- **撤稿不删图片**：只删除笔记文件本身。
- **属性（frontmatter）白名单**：发布副本只保留白名单中的属性，默认 `title`、`tags`、`date`、`description`，其余一律去除（避免私人属性上网）；白名单可在设置中修改。vault 原文不受影响。

## 8. 站点隔离（身份保护）

- 开启隔离的站点：任何指向**其他站点**的链接一律输出为纯文本，绝不输出其他站点的网址。
  - **v1 补充（2026-10-04 用户决定）**：目标笔记不在本站、但已发布在其他站点时，**非隔离站点输出另一站点的完整网址**；**指向隔离站点上的笔记时，其他站点同样输出纯文本**（双向不链接，避免暴露关联）；目标同时在本站与他站时优先本站。
- 不向页面注入任何与 GitHub 账号、仓库相关的信息。
- 连带发布不会把笔记发到用户未选择的站点。

## 9. 数据：manifest

- 每个站点仓库内存一份 `.pressroom/manifest.json`（位于内容目录之外，不会被站点发布）。仓库即唯一真相源，换设备、重装插件不丢。
- manifest 顶层记录站点目录模式（手动 / 跟随 vault），换设备保持一致；设置页修改模式即写回仓库。
- 每条记录：vault 路径、站内路径、站内名称、上传的附件列表、最近发布的 blob SHA、发布时间。
  - **隐私说明（2026-10-03 用户决定维持明文）**：vault 路径以明文存于站点仓库，仓库公开时会暴露 vault 目录结构，多个站点的 manifest 也可能被关联；由用户自行保证站点仓库私有（曾考虑存每站加盐哈希或移到本机，未采用）。README 中需提示这一点。
- 监听 vault 的改名/移动事件，更新 manifest 中的源路径（站内路径不变；跟随 vault 站点的笔记因此显示「已移动」）。
  - **v1 补充（2026-10-04 用户决定）**：改名后**自动提交**写回仓库（只改 manifest 源路径）；几秒内的多次改名合并为一次提交；离线或失败时记在本地，下次操作或插件加载时补提交。
- 首次接管已有站点：提供「导入已有内容」，把仓库内容目录中的现有文件与 vault 笔记按路径匹配，生成 manifest（用于从 Enveloppe 迁移）。

## 10. 实现要点

- GitHub 写入使用 Git Data API（blob → tree → commit → 更新分支 ref），一次操作一次提交；不创建分支、不开 PR。
- 网址规则与 Quartz 5 `slugifyFilePath` 保持一致，并有单元测试覆盖中文、空格、大小写、特殊字符。**v1：直接依赖 Quartz 5 所用的 npm 包 `@quartz-community/utils`（`/path` 子模块，MIT，纯函数），不自行重写**；单元测试用 Phase 0 用例表。
- GitHub 更新 ref 遇 422（非 fast-forward，如多设备同时发布）时：重新取 ref、重读 manifest、重建提交，有上限地重试。
- token 用 `secretStorage` + `SecretComponent`（data.json 只存密钥 id），`minAppVersion` 为 ~~1.11.4~~ **1.13.0**（2026-10-03 用户决定：设置页采用 1.13 起的声明式设置 API，旧的 `display()` 写法已弃用，且声明式设置项可进入 Obsidian 设置搜索）。
- 发布完成后提示「约 1 分钟后生效」（站点构建时间）。
