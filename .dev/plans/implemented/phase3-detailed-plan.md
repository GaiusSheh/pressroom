# Phase 3: 完整内容转换与隔离 详细计划

## 计划概述
**阶段名称**: Phase 3 - 完整内容转换与隔离  
**核心目标**: 嵌入笔记展开、跨站链接与站点隔离、反向链接提醒，以及支撑它们的「多篇一次提交」  
**当前状态**: [✓] 已完成，人类验收通过（2026-10-04）  
**依据**: 需求 v1 §7、§8（2026-10-04 修订：连带发布只在跟随 vault 站点提供；新增反向链接提醒）；Phase 2 的转换与发布服务（`.dev/plans/implemented/phase2-detailed-plan.md`）  
**不在本阶段**: 连带发布（随跟随 vault 模式移到 Phase 4）；「全部站点」（Phase 4）；管理面板（Phase 5）

## 已确认的决定（2026-10-04）
- **连带发布只在跟随 vault 站点提供**，连带笔记的位置即其 vault 位置；手动站点中未发布的链接一律纯文本，发布弹窗列出它们并说明「你可以先发布这一篇。等它们发布后，Pressroom 会提醒你更新这一篇，链接就会生效」→ 连带收集、确认清单、更新时的连带处理整体移到 Phase 4
- **跨站链接**：非隔离站点输出另一站点的完整网址；隔离站点输出纯文本；指向隔离站点上的笔记时，其他站点也输出纯文本；目标同时在本站与他站时优先本站
- **嵌入展开**：包在 callout 中并显示被嵌入笔记的标题
- **反向链接提醒**：发布后列出链接到它的已发布笔记，提供「一并更新」；撤稿确认框提供「一并更新，链接改为纯文本」（默认勾选）；不自动更新，只影响一层

## 现状分析

### 已有基础（Phase 2）
- [✓] `core/transform/transform.ts`：按 refs 偏移替换；嵌入笔记目前临时变纯文本（`rewrite` 的 `note` 分支）
- [✓] `core/publish.ts`：单篇 `publishNote` / `unpublishNote` 各在一次提交内完成；`prepare` 负责附件分配与转换
- [✓] `platform/vault.ts`：`parseNote`（metadataCache → ParsedNote，校验偏移原文）
- [✓] `ui/actions.ts`：站点快照 30 秒缓存；`ui/location-modal.ts`：首次发布位置弹窗

### 关键 Obsidian API（实现前在 `obsidian.d.ts` 核对）
- `resolveSubpath(cache, subpath)`：`#标题` / `#^块` → 正文范围
- `metadataCache.resolvedLinks`：反向链接查找（哪些笔记链接到某篇）

## 架构约定
```text
src/core/
├── transform/
│   ├── transform.ts   # 改为接收已展开的嵌入；新增跨站链接与隔离判断
│   └── embed.ts       # （新增）嵌入展开：递归、防循环、深度上限、callout 包裹
├── backlinks.ts       # （新增）本站已发布、链接到某篇的笔记
└── publish.ts         # publishNotes / unpublishNotes：多篇一次提交；跨站查询

src/ui/

```
- 嵌入展开在转换前**异步**完成（读取被嵌入笔记），转换本身保持同步纯函数。
- 多篇发布：转换时「本站已发布」的查询包含本批所有笔记，批内互相链接正确。

## 详细实施步骤

### Phase 3-1: 多篇一次提交（`core/publish.ts`）
#### 具体任务
- `publishNotes([{ note, sitePath? }])`、`unpublishNotes(vaultPaths, { alsoUpdate })`：所有笔记、附件、manifest 在一次提交内完成（需求 §6.2；Phase 4 连带、Phase 5 批量按钮复用）
- 转换时「本站已发布」的查询 = manifest + 本批笔记的目标位置（撤稿时去掉本批撤下的）
- 本批任一笔记网址冲突 → 整批不提交，报告全部冲突
- 原 `publishNote` / `unpublishNote` 改为单篇形式的封装，Phase 2 单元测试保持通过
#### 验收标准
- [✓] 单元测试（假 GitHub）：多篇一次提交、批内互链、批内冲突整批拒绝、共享附件只传一次、撤稿 + 一并更新在同一提交、非 fast-forward 重试后整批正确、Phase 2 测试全部通过

### Phase 3-2: 嵌入笔记展开（`core/transform/embed.ts`）
#### 具体任务
- `![[笔记]]` 展开整篇正文（去掉 frontmatter）；`![[笔记#标题]]` 展开该标题段；`![[笔记#^块]]` 展开该块
- 包在 callout 中，标题为被嵌入笔记的标题（frontmatter `title`，否则文件名；带子路径时附上标题名）；嵌套嵌入使用嵌套 callout
- 被嵌入内容同样转换：链接以**被嵌入笔记的路径**解析，图片 / 附件照常收集上传
- 防循环：展开链上已出现的笔记再次出现时停止，输出纯文本名称；深度上限 10
- 被嵌入笔记在排除文件夹中 → 不展开，输出纯文本名称；无法解析 → 纯文本
- 被嵌入笔记不单独成页、不被带出；它修改后，嵌入它的已发布笔记状态变为「有修改」（blob SHA 比较自然得到）
- 先在测试 vault 实测 `resolveSubpath` 对标题下嵌套列表、列表项中的块等结构的范围，再定实现；callout 写法在本地 Quartz 实际构建验证（含嵌套 callout）
#### 验收标准
- [✓] Quartz 实际构建：callout（含嵌套）、其中的链接与图片正确显示
- [✓] 测试 vault 实测：与 Obsidian 阅读模式对照，标题段、块的展开范围一致
  - **实测修复**：带 `#` 的嵌入，Obsidian 的 displayText 自动为「笔记 > 标题」，被误判为用户别名，callout 标题用了文件名 → 自定义显示文字改为按原文判断（维基链接看 `|`）；展开内容行尾的 ` ^id` 块标记去掉（避免宿主页出现重复块 id）
- [✓] 单元测试：整篇 / 标题 / 块、嵌套、循环（A↔B、A→A）、深度上限、排除、被嵌入内容中的链接与图片按被嵌入笔记路径解析、输出稳定

### Phase 3-3: 跨站链接与站点隔离（需求 §8）
#### 具体任务
- 目标不在本站：查其他站点的 manifest（复用快照缓存）；在非隔离站点上 → 非隔离的本站输出该站完整网址；目标站或本站隔离 → 纯文本
- 只在本篇存在「本站未发布」的链接时才读取其他站点；本站隔离时不读取
- 目标同时在本站与他站时优先本站
- 他站状态变化（如目标在 B 站撤稿）后，A 站引用它的笔记状态变为「有修改」
- 自查：发布副本与提交信息中不出现 GitHub 账号、仓库名、vault 路径
#### 验收标准
- [✓] 单元测试：非隔离 → 他站网址；本站隔离 → 纯文本；目标站隔离 → 纯文本；优先本站；他站撤稿后状态变化
- [✓] 测试 vault 实测：第二个站点 ~~（同一测试仓库的 `content2/` 内容目录）~~ **（同一测试仓库的 `site2` 分支）** 验证跨站链接与隔离：非隔离 → 他站网址（含锚点）；本站隔离 → 纯文本；目标站隔离 → 纯文本且「已是最新」；恢复后链接回来
  - **[!] 实测发现**：两个站点指向同一仓库同一分支时共用 `.pressroom/manifest.json`，互相把对方的发布当成自己的（生成站内死链、误判状态）→ **用户决定（2026-10-04）**：禁止同仓库同分支，同仓库不同分支允许；设置页字段校验（`findRepoBranchClash`）+ 操作入口跳过冲突站点并提示

### Phase 3-4: 反向链接提醒（`core/backlinks.ts` + 界面）
#### 具体任务
- 找出本站已发布、且在 vault 中链接到目标笔记的笔记（Obsidian `resolvedLinks` 反查，与 manifest 求交）
- 发布成功提示：「有 N 篇已发布的笔记链接到它，现在更新它们就能显示链接」+「一并更新」按钮 → 一次提交
- 撤稿确认框：列出链接到它的已发布笔记，选项「一并更新，链接改为纯文本」默认勾选 → 撤稿与更新同一提交
- 一并更新的笔记会带上它们在 vault 中尚未发布的其他改动：提示文字中说明
#### 验收标准
- [✓] 单元测试：反查结果（排除未发布、排除本篇自身、嵌入与链接都计入）
- [✓] 测试 vault 实测：发布后「一并更新 1 篇」与撤稿时一并更新（单个提交「更新 …；撤稿 …」）结果正确；「取消勾选时不更新」由单元测试覆盖（`publishBatch` 不带 items）
  - 调整：这两个操作耗时数秒，原先期间无提示、完成提示过短被错过 → 增加「正在更新…」「正在撤稿…」进度提示，完成提示停留 10 秒

### Phase 3-5: 手动站点的未发布链接说明（`ui/location-modal.ts`）
#### 具体任务
- 首次发布弹窗：列出本篇中未在本站发布的笔记（最多显示若干篇，其余「等 N 篇」），说明「你可以先发布这一篇。等它们发布后，Pressroom 会提醒你更新这一篇，链接就会生效」；没有这类链接时不显示
- 更新已发布笔记时不弹窗，行为不变
- 设置页「指向未发布笔记的链接」的说明改为「只对跟随 vault 的站点生效；手动站点中这类链接显示为纯文本」
#### 验收标准
- [✓] 测试 vault 实测：有未发布链接时列出并显示说明（中文）
  - 调整：已发布在其他站点、会输出跨站链接的笔记不再列为「将显示为纯文本」（实测误报，改为与转换共用跨站查询）

### Phase 3-6: 端到端验证
#### 具体任务
- 测试 vault 补充示例：三种嵌入、嵌套嵌入、循环嵌入、指向排除文件夹的嵌入、跨站链接
- windows-mcp 测试 agent 执行 GUI 测试（3-2、3-3、3-4、3-5 的实测项）；把测试仓库内容拉到本地 Quartz 构建（复用 `.dev/tests/phase2/quartz/sandbox-build.mjs`）
#### 验收标准
- [✓] Quartz 构建后 callout 展开内容、站内与跨站链接、图片正确；隔离站点页面中不出现其他站点网址
