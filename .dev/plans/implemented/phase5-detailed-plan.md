# Phase 5: 管理面板 详细计划

## 计划概述
**阶段名称**: Phase 5 - 管理面板  
**核心目标**: ribbon 呼出的管理面板（站点选项卡 + 站内目录树 + 状态）；单项操作；批量「一键同步 / 更新 / 重排 / 清理已删除」；文件列表多选批量发布 / 撤稿  
**当前状态**: 5-1 ~ 5-6 完成（单元测试 399 项；GUI 11 步通过；Quartz 构建验证移动 / 重排后旧网址跳转），2026-10-05 人类验收通过  
**依据**: 需求 v1 §4（多选、命令面板）、§5.3（站内改名 / 移动弹窗）、§6、§6.1、§6.2、§11（aliases）；Phase 4 的挪动 core（`publishBatch` 在跟随站点自动挪动）、`noteStatus`（含 moved）、`deletedSources`、`LocationBlock`  
**不在本阶段**: 「导入已有内容」、README、发布流程（Phase 6）

## 现状分析

### 已有基础
- [✓] `core/publish.ts`：`publishBatch`（多篇一次提交、撤稿、跟随站点挪动 + aliases）、`noteStatus`（synced / modified + moved）、`deletedSources`、`loadSnapshot`（含未写回的改名）
- [✓] `ui/location-modal.ts`：`LocationBlock`（目录 / 名称 / 网址预览 / 冲突与忽略提示），可复用于「站内改名 / 移动」
- [✓] `ui/actions.ts`：快照缓存、`runOnSites` 汇总提示、反向链接提醒、`commitMessage`（含挪动）
- [✓] 右键菜单与命令面板的四个单篇命令（Phase 2 起）

### 缺口
- [!] `publishBatch` 目前在跟随站点**总是**挪动：「一键更新」（原位置更新、已移动保留）需要「不挪动」选项
- [!] 手动站点的移动需要「已发布笔记指定新位置」的入口（`PublishItem.sitePath` 目前只对首次发布生效）
- [!] 「一键重排」（只挪位置、有修改保留）与 aliases 的写入方式冲突，见讨论项 1
- [!] 面板要计算本站全部已发布笔记的状态：每篇需解析笔记、预加载嵌入、读附件，篇数多时较慢（deferred 中已记站点读取性能）

## 架构约定
```text
src/core/
├── publish.ts        # publishBatch 增加 BatchOptions.move：'auto'（默认，跟随站点挪动）| 'never'（一键更新）
│                     # PublishItem.moveTo：已发布笔记移到指定站内路径（手动站点的站内改名 / 移动；写 aliases）
│                     # relocateBatch（一键重排，按讨论项 1 的结论实现）
├── panel.ts          # 面板数据（纯逻辑）：manifest + 状态 → 站内目录树节点；各批量按钮的作用对象筛选与计数
└── ...
src/ui/
├── panel/
│   ├── panel-modal.ts  # ribbon 弹窗：站点选项卡、目录树、批量按钮、刷新

│   └── status-loader.ts# 逐篇计算状态（并发上限、进度、可取消）

└── menu.ts           # files-menu（多选）、ribbon、新命令
```

## 详细实施步骤

### Phase 5-1: core 补齐（需求 §5.3、§6.2）
#### 具体任务
- `BatchOptions.move: 'auto' | 'never'`：`never` 时跟随站点的已发布笔记在原位置更新，manifest 的 sitePath 不变（「已移动」保留）
- `PublishItem.moveTo`：已发布笔记移到指定站内路径（手动站点用）；冲突检测排除自身旧位置；删旧、写新、旧路径写入 aliases（与跟随站点的挪动共用一段逻辑）
- 一键重排（用户决定 A）：`relocateBatch` 读取旧发布副本，只在 frontmatter 中合并 aliases、正文保持旧版本，写到新位置并删旧；manifest 的 sitePath / aliases 更新，blobSha 记为新文件的 SHA，因此「有修改」照旧显示；`relative` 链接策略的站点拒绝（面板中不提供该按钮）
- `core/panel.ts`：把 manifest 记录组织成站内目录树（按站内路径分层；文件夹笔记折叠规则与网址一致）；按状态筛选各批量按钮的作用对象（同步 = 有修改或已移动；更新 = 有修改；重排 = 已移动；清理 = 源已删除）
#### 验收标准
- [✓] 单元测试：`move: 'never'` 原位更新；`moveTo` 挪动（删旧 / 写新 / aliases / 冲突拒绝 / 挪回去掉 alias）；重排（正文不变、aliases 合并、有修改保留、relative 拒绝）；目录树构造；各按钮的筛选与计数

### Phase 5-2: 面板框架与目录树（需求 §6）
#### 具体任务
- 左侧 ribbon 图标 + 命令「打开管理面板」→ 弹窗（与 Obsidian Publish 一致，非常驻侧栏）
- 顶部每个站点一个选项卡（只列可用站点；仓库 + 分支重复的站点不列出并提示）
- 主体：站内目录树，每项显示站内名称、对应的 vault 路径、状态标签（✓ 已同步 / ● 有修改 / ↪ 已移动 / ✗ 源笔记已删除）；文件夹可折叠
- 打开选项卡时读取快照、逐篇计算状态：先显示目录树与「计算中」，状态逐篇填入；并发上限、可刷新；切换选项卡时缓存
- 目录树只显示 Pressroom 管理的笔记（manifest 记录，用户决定 A）
#### 验收标准
- [✓] 测试 vault 实测：两个站点选项卡、目录树层级与状态标签正确；大量笔记时界面不卡死（逐篇填入）

### Phase 5-3: 单项操作（需求 §6）
#### 具体任务
- 每项的操作菜单：更新、站内改名 / 移动（仅手动站点）、撤稿、复制链接、打开网页、在 vault 中打开
- 更新、撤稿复用现有流程（含反向链接提醒、撤稿确认框的一并更新）
- 站内改名 / 移动：`move-modal.ts` 复用 `LocationBlock`，预填当前站内位置，「按 Vault 目录」作为快捷方式；确认前看到网址预览与冲突检查；未开别名跳转时提示旧链接失效
- 源笔记已删除的项：只提供撤稿、复制链接、打开网页
- 操作完成后刷新该站的面板数据
#### 验收标准
- [✓] 测试 vault 实测：六种单项操作；手动站点移动后旧网址跳转（Quartz 构建）；跟随站点不显示移动

### Phase 5-4: 批量按钮（需求 §6.2）
#### 具体任务
- 面板顶部按钮（作用于当前站点），按钮上显示数量，数量为 0 时禁用：
  - 跟随 vault 站点：一键同步、一键更新、一键重排（`relative` 链接策略的站点不显示）、清理已删除 (n)
  - 手动站点：一键更新、清理已删除 (n)
- 每个批量操作合并为一次提交；执行前列出清单确认（清理已删除必须先列清单）
- 跟随站点的一键同步 / 更新：新出现的未发布链接按设置默认值处理（默认为连带时弹连带清单，与单篇一致），绝不静默多发
- 执行期间显示进度，完成后刷新面板并汇总
#### 验收标准
- [✓] 单元测试：批量操作一次提交、提交信息
- [✓] 测试 vault 实测：四个按钮的计数、确认清单、执行后状态

### Phase 5-5: 文件列表多选与命令（需求 §4）

## 实施调整记录（2026-10-05）

- **aliases 顺序 bug（单元测试发现）**：manifest 序列化时 aliases 排序，发布副本按写入顺序；挪动后有 2 个以上 aliases 时，读回再渲染与站上副本不一致，被误判「有修改」。修正：`mergeAliases` 中 Pressroom 的 aliases 一律按码点排序；重排改写旧副本时先去掉上次的 Pressroom aliases 再合并（补了回归测试）
- **面板单项「更新」= 右键发布的单站流程**（`publishOnSite`）：跟随站点上已移动的笔记会同步到新位置（与 2026-10-04 决定一致）
- **一键同步 / 更新的连带**：多篇合并收集，一个连带清单；设置默认为纯文本时不询问
- **状态计算**：并发 4 篇，逐篇填入；全部算完前批量按钮禁用，避免只作用于部分笔记
- **多选撤稿不做反向链接的一并更新**（单篇撤稿保留）
- **GUI 反馈修正**：站点未开别名跳转时，同步 / 重排确认框不再写「旧网址会跳转」，改为提示旧网址将失效；计数为 0 的按钮淡化显示、「清理已删除」只在有内容时用警示色；面板主体固定高度，条目变化时弹窗不再跳动

## 需要讨论（开工前请确认）

> **2026-10-05 用户决定**：第 1 项选 **A 只改 aliases**；第 2 项选 **A 只显示 Pressroom 管理的笔记**；第 3 项选 **B 跳过并说明**。

1. **一键重排（只挪位置、复用原 blob、「有修改」保留）与 aliases 冲突**：旧网址跳转要求新位置的发布副本 frontmatter 写入 aliases，这会改变文件内容，无法原样复用旧 blob；另外站点用 `relative` 链接策略时，正文里的相对链接换了位置会失效
   - A. 重排时读取旧发布副本，只改 frontmatter 的 aliases、正文保持旧版本（「有修改」保留）；`relative` 策略的站点不提供一键重排，只提供一键同步
   - B. 去掉「一键重排」，跟随站点只保留一键同步 / 一键更新
2. **目录树显示范围**：
   - A. 只显示 Pressroom 管理的笔记（manifest 中的记录）
   - B. 显示内容目录中的全部文件，非 Pressroom 管理的灰显、不可操作（能看到完整网站结构与可能的网址冲突）
3. **多选发布时，手动站点上尚未发布的笔记**：
   - A. 弹一个窗口统一选择站内目录，各篇保持 vault 文件名（逐篇冲突检测，冲突的列出不发布）
   - B. 跳过并在结果中说明「请逐篇发布以选择位置」，只更新已发布的、以及发布到跟随站点

## 技术风险评估

### 中风险项
- **面板状态计算慢**：每篇需解析、预加载嵌入、读附件
  - 缓解措施: 目录树先出、状态逐篇填入；并发上限；选项卡缓存；刷新按钮
- **批量操作的连带**：一键同步可能带出大量连带笔记
  - 缓解措施: 与单篇共用连带清单与 50 篇额外确认

### 低风险项
- **多选的 `files-menu` 事件**：公开 API（`obsidian.d.ts` 中 `workspace.on('files-menu', (menu, files, source, leaf))`，已核对）；ribbon 用 `addRibbonIcon`
