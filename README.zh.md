# Pressroom

[English](README.md)

把 Obsidian 笔记逐篇发布到一个或多个 [Quartz 5](https://quartz.jzhao.xyz/) 网站（网站源文件放在 GitHub 仓库中）。右键一篇笔记、选一个站点，大约 1 分钟后网页就能打开。

- **逐篇发布**：只有你主动发布的笔记才会上网，其他笔记都留在本地。
- **不改你的笔记**：不会往笔记里加任何属性或标记，上网的是另外生成的副本。
- **多个网站**：同一篇笔记可以发到一个、几个或全部站点。
- **管理面板**：一眼看到哪篇发在哪里、哪些有修改，并能批量更新、移动或撤下。

仅支持桌面端，适用于放在 GitHub 仓库中的 Quartz 5 网站。

## 开始前需要准备

1. **一个 Quartz 5 网站**：源文件在 GitHub 仓库里，已经部署好（比如用 GitHub Pages 或 Cloudflare Pages），有自己的网址。
2. **一个 GitHub token**：用 [fine-grained token](https://github.com/settings/personal-access-tokens)，只给站点仓库 **Contents 读写** 权限即可。Pressroom 把它存在 Obsidian 的密钥库里，不写进插件数据。
3. **建议把站点仓库设为私有**：Pressroom 会在每个站点仓库里保存一份已发布笔记的清单（`.pressroom/manifest.json`），其中包括每篇笔记在 vault 中的位置。仓库公开时，别人能看到你 vault 的文件夹名。

## 安装

Pressroom 上架 Obsidian 社区插件后，在「设置 → 第三方插件 → 浏览」中搜索 **Pressroom** 安装。

上架之前，从本仓库 Releases 页面的最新版本下载 `main.js`、`manifest.json`、`styles.css`，放进 `<你的 vault>/.obsidian/plugins/pressroom/`，再在「设置 → 第三方插件」中启用 Pressroom。

## 设置

### 发布

| 设置项 | 作用 |
|---|---|
| GitHub token | 填入上面准备的 token。 |
| 排除文件夹 | 这些文件夹里的笔记永远不会被发布，也不会被别的笔记连带出去，比如 `Private`。每行一个。 |
| 指向未发布笔记的链接 | 笔记链接到的另一篇还没在站上时，默认怎么处理：变成纯文本 / 连带发布一层 / 顺着链接一直发布下去。只对「跟随 vault」的站点生效。 |
| 发布副本保留的属性 | 笔记 frontmatter 中只有这些属性会带上网（默认 `title`、`tags`、`date`、`description`），其余（比如写给自己的备注）一律去掉。 |

### 站点

点「添加站点」，填写：

| 项目 | 说明 |
|---|---|
| 名称 | 在菜单中显示，比如「站点 A」。 |
| 仓库 | `owner/repo`。 |
| 分支 | 一般是 `main`。同一仓库的同一分支只能配一个站点（同一仓库的不同分支可以）。 |
| 内容目录 | Quartz 读取笔记的文件夹，一般是 `content`。 |
| 站点网址 | 比如 `https://example.pages.dev`，用于生成链接。 |
| 目录模式 | 见下文。 |
| 隔离此站点 | 打开后，本站指向你其他站点的链接一律变成纯文本，外人看不出这几个站属于同一个人。 |
| 测试连接 | 检查 token、仓库、分支和 Quartz 配置，不写入任何内容。 |

**目录模式**决定笔记放在网站的什么位置：

- **手动**（默认）：每篇第一次发布时，由你决定它在网站上的文件夹和名称，和 vault 里怎么放无关。
- **跟随 vault**：网站结构与 vault 完全一致。vault 里的 `读书/某本书.md` 发布后就在网站同样的位置，不需要填写位置。

目录模式保存在站点仓库里，换一台设备也保持一致。

## 日常使用

在文件列表中右键一篇笔记（或用命令面板）：

| 菜单 | 作用 |
|---|---|
| **Pressroom：发布…** | 发布；已发布过的就是更新。 |
| **Pressroom：撤稿…** | 从网站上删掉这一页，vault 里的笔记不变。 |
| **Pressroom：获取链接…** | 复制这篇在网站上的网址。 |
| **Pressroom：打开网页…** | 在浏览器中打开这一页。 |

随后会弹出站点列表，每个站点后标着这篇在该站的状态：

| 状态 | 意思 |
|---|---|
| ✓ 已同步 | 网站上的和 vault 里的一样。 |
| ● 有修改 | 你改过笔记，网站上还是旧版本。 |
| ↪ 已移动 | 只在「跟随 vault」站点出现：你在 vault 里改了名或挪了位置，网页还在原处。 |
| 未发布 | 还没发到这个站。 |

列表最后的「**全部站点**」可以一次发布到、撤下或复制所有站点的链接。只配置了一个站点时不弹列表，直接执行。

### 第一次发布

- **手动站点**会弹出位置窗口：填写站内目录和名称（「填入 vault 位置」按钮可以一键填入 vault 中的目录与文件名），网址预览实时更新。如果和站上已有页面的网址冲突（Quartz 把 `A B` 与 `a-b` 视为同一个网址），要换个名字才能发布。
- **跟随 vault 站点**不需要填位置。如果本篇链接到还没在本站发布的笔记，会询问是把这些链接变成纯文本，还是把它们一起发布，并可以逐篇取消勾选。

### 发布时会自动处理的内容

- **链接**（`[[另一篇]]`）：那篇已在本站，变成站内链接；只发在另一个站，链接到那个站（任一站开启隔离时为纯文本）；哪里都没发，变成纯文本。
- **图片和附件**随笔记一起上传；同一个文件被多篇引用只存一份。
- **嵌入**（`![[某篇]]`）的内容直接展开写进这一页，外面套一个带标题的引用框，效果类似 Obsidian。
- **反向链接提醒**：发布一篇后，如果站上已有别的笔记链接到它（之前只能显示为纯文本），提示里会提供「一并更新」，点一下链接就生效；撤稿时默认把指向它的链接改回纯文本，不留死链。

## 改名与移动

- 在 vault 中给已发布的笔记改名或换文件夹，Pressroom 会记下新位置，几秒内写回各站点仓库（离线时联网后补上）。
- 「跟随 vault」站点上，这篇会显示「↪ 已移动」。再发布一次，网页就挪到新位置，**旧网址会自动跳转到新页面**，别人收藏的链接不会失效。这依赖 Quartz 的别名跳转（默认开启）。
- 「手动」站点上网页位置不变，需要时在管理面板中移动。

## 管理面板

点左侧边栏的报纸图标，或运行命令「Pressroom: 打开管理面板」。

- 每个站点一个选项卡，显示网站的目录结构，列出所有用 Pressroom 发布的笔记：站内名称、在 vault 中的位置、状态。笔记多时状态会逐篇出现。
- 多一种状态「✗ 源笔记已删除」：网站上还有这一页，但 vault 里的笔记已经删了。

每一项右边的「…」：更新、站内改名 / 移动（只在手动站点，旧网址会跳转）、撤稿、复制链接、打开网页、在 vault 中打开。

顶部按钮作用于整个站点（括号里是涉及的篇数）：

| 按钮 | 作用 | 适用站点 |
|---|---|---|
| 一键同步 | 更新所有有修改的，并把已移动的挪到 vault 中的位置 | 跟随 vault |
| 一键更新 | 只更新内容，已移动的留在原处 | 全部 |
| 一键重排 | 只把已移动的挪到 vault 中的位置，不推送新内容 | 跟随 vault（使用相对链接的站点除外） |
| 清理已删除 | 撤下源笔记已删除的页面 | 全部 |

每个批量操作都会先列出清单请你确认，确认后一次提交。

## 一次处理多篇

在文件列表中按住 **Shift** 点选多篇（Obsidian 中 Ctrl+单击是在新标签页打开），右键选择「发布所选 N 篇…」或「撤稿所选 N 篇…」。手动站点上还没发布过的笔记会跳过（每篇的位置需要你逐篇决定一次），结果中会说明跳过了几篇。

## 需要知道的几点

- 发布后大约 1 分钟网站才更新，这是 Quartz 重新构建所需的时间。
- 每次操作在站点仓库中只产生一次提交，不论涉及多少篇。
- Pressroom 需要的信息都存在站点仓库里，换一台设备装好插件、填上同样的站点就能接着用。
- 仓库里在使用 Pressroom 之前就已存在的页面（比如用其他工具发布的）保持原样，Pressroom 只用它们来避免网址冲突。

## 开发

Windows 下请在 PowerShell 中运行 npm（Git Bash 下 npm 安装脚本会失败）。

```powershell
npm install
npm run dev     # 监听构建
npm run build   # 类型检查 + 生产构建
npm test        # 单元测试
npm run lint
```

- 源码：`src/`；核心逻辑在 `src/core/`，不依赖 `obsidian` 包，可在 Node 中单元测试。
- 单元测试：`.dev/unit-tests/`（vitest）。
- 测试 vault：`.dev/unit-tests/test-vault/`。在根目录 `.env.local` 写入 `PRESSROOM_VAULT=<vault 绝对路径>`，构建后产物会自动复制到该 vault 的插件目录。
